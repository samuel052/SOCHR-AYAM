# UX Spec: רצף פתיחת יום, אירועי בוקר ולוח המודעות (Day Events)

> **Template**: UX Spec

## Purpose & Player Need

לקבל את "חדשות הבוקר" בקצב נעים ולהחליט על הצעות — בדיוק כרצף המקור: יום ←
מזג אוויר ← אירוע ← מסך ראשי. הכרזות פסיביות בלוח המודעות; אירועים אישיים
כסצנות על רקע הנמל (docx).

## Player Context on Arrival

אוטומטי — אחרי מנוחה/דילוג יום/משחק חדש. רגע "פתיחת מתנה"; מותר רגע של דרמה.

## Navigation Position / Entry & Exit

‏rest()/new_game() → **day-sequence** (רצף מודאלי) → port-hub. אין יציאה באמצע;
כל כרטיס דורש "המשך" (P2) או החלטה (P3).

## Layout Specification

### רצף הכרטיסים (P2, בזה אחר זה)

1. **כרטיס יום**: "יום שלישי" + איור זריחה בנמל (שחזור מסכי DAYx.SGN).
2. **כרטיס מזג אוויר**: "מזג האוויר נאה" / "סערה מתחוללת ליד חופי [נמל]" —
   בהתאמה ל־GOODWTHR/BADWTHR של המקור. ביום 1 תמיד נאה.
3. **כרטיס אירוע** (מיום 2) — אחד מ:
   - שינוי מחיר: מתפרסם **בלוח המודעות** (docx) — הכרטיס מציג את הלוח מתקרב
     עם המודעה: "מחיר הנחושת זינק במרסין! 4,300 ש"ח".
   - גניבה / סירת דיג: כרטיס סצנה על רקע הנמל + הסכום/הכמות (נוסח המקור).
   - סוחר קונה/מוכר, הרחבת ספינה, שביתת צוות: **Decision Dialog** (P3) —
     סצנת דמות על רקע הנמל + פרטי ההצעה + כפתורים.

### דיאלוגי ההחלטה

| אירוע | תוכן | כפתורים |
|---|---|---|
| סוחר קונה | "הסוחר מציע לקנות את כל ה[סחורה] שלך — X טון ב־Y לטון (סה"כ Z)" | קבל / דחה |
| סוחר מוכר | "הסוחר מציע X טון [סחורה] ב־Y לטון (סה"כ Z)" | קבל / דחה |
| הרחבת ספינה | "+Δ טון תמורת [פירוט התשלום]" (כסף/סחורה/שילוב — מה־context) | קבל / דחה |
| שביתת צוות | "הצוות מאיים לנטוש!" + הסבר ההשלכות (יום אבוד / מו"מ) | ויתור (יום אבוד) / מו"מ |
| מו"מ צוות | ‏4 Pickers (כסף+3 סחורות) + "שווי ההצעה" חי | הצע / חזרה לבחירה |

תוצאת מו"מ כושל: כרטיס "הצוות דחה את הצעתך — אובדים יומיים" ← קפיצה לרצף היום החדש.

### לוח המודעות (ב־hub)

hotspot קריאה חוזרת: מציג את מודעות היום — מזג האוויר + אירוע המחיר אם היה
(docx: "בלוח המודעות יופיעו הודעות על מזג אוויר חריג... וכן עליית מחירים").
אירועים אישיים (גניבה, סוחר) אינם בלוח.

## States & Variants

| מצב | טריגר | שינוי |
|---|---|---|
| יום 1 | new_game | כרטיס יום + "נאה" בלבד, ללא אירוע |
| דילוג ימים | שביתה | כרטיס מעבר "עברו X ימים" לפני רצף היום החדש |
| הצעה לא חוקית במו"מ | מעל המצוי | שגיאה מקומית, הדיאלוג נשאר |

## Interaction Map / Events Fired

"המשך" — קלט בלבד; החלטות — `answer(id, payload)`. הרצף כולו מוזן מ־
`day_started(announcements)` + ‏`decision_required` (ADR-0001) — ה־UI לא מגריל דבר.

## Transitions & Animations

כרטיסים ב־fade+scale ‏150ms; לוח המודעות "מתקרב" 250ms; ‏reduced-motion: חיתוך.

## Data Requirements

קריאה: announcements (day, storm_port, morning_event/decision context). כתיבה:
`answer()` בלבד.

## Accessibility

אין timeout; ‏Enter מתקדם; כל האיורים מלווים בטקסט מלא.

## Localization Considerations

כל הנוסחים `# original` מטבלת המחרוזות; מספרי ימים בעברית ("יום ראשון"…).

## Acceptance Criteria

- [ ] רצף יום 1: שני כרטיסים בלבד; מיום 2: שלושה (או שניים+דיאלוג).
- [ ] כל 7 משפחות האירועים ממופות לכרטיס/דיאלוג הנכון (drift test מול DecisionRouter).
- [ ] סירוב לכל הצעה משאיר את המצב ללא שינוי (נבדק מול snapshot).
- [ ] מו"מ צוות: הצעה שווה לרף נכשלת (עוברת דרך המנוע) ומציגה את כרטיס הכישלון הנכון.
- [ ] לוח המודעות ב־hub משחזר את מודעות היום בכל רגע.
- [ ] הרצף כולו מתקדם בעכבר בלבד ובמקלדת בלבד.
