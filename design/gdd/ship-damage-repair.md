# GDD — ספינה, נזק ותיקון (ship-damage-repair)

> שכבה: Core | סטטוס: Draft | מקורות: `תוכנית.txt`, `סיכום אירועי הפלגה מהודק.txt` [7], `התפלגות סיכויים.txt` (רציף סגור), צילומי מסך `לתקן את הספינה/`
> מוסכמה: `rand(n)` = שלם אחיד `0..n-1`; חלוקה שלמה = קיטום.

## 1. Overview

לספינה שני מאפיינים מתמשכים: **קיבולת** (מתחילה ב־100 טון, גדלה דרך expand/לכידת ספינת שודדים) ו**נזק** (סכום בשקלים, 0 = תקינה). נזק נצבר מאירועים (סירת דיג, סערה, שרטון, פיראטים, נסיעה בספינה פגועה), מוצג לשחקן, ומתוקן ברציף התיקונים תמורת כסף. נזק מעל 1,000 ש"ח חוסם הפלגה.

## 2. Player Fantasy

הספינה היא הבית והעסק — כשהיא פגועה, מרגישים את זה: היא נראית פגועה במסך ההפלגה, איטית לברוח, ומסוכנת להפליג בה. תיקון הוא הוצאה כואבת אך הכרחית, והחלטת "לתקן עכשיו או להסתכן" היא דילמה חוזרת.

## 3. Detailed Rules

1. **קיבולת**: ערך התחלתי 100 טון. גדלה רק דרך: עסקת expand (אירוע בוקר, +50/+100), לכידת ספינת שודדים (+50; ראו `pirates.md`). לא קטנה לעולם.
2. **נזק**: מספר שלם ≥ 0 בשקלים. מצטבר (כל אירוע נזק מוסיף). ערך הנזק = עלות התיקון המלא.
3. **חסימת הפלגה**: אם `damage > 1000` — אסור להפליג עד תיקון שמוריד את הנזק ל־1,000 או פחות (`תוכנית.txt`).
4. **תיקון**: אפשרות "לתקן את הספינה" מופיעה בתפריט רק כאשר `damage > 0`. השחקן משלם סכום X במזומן ⇒ `damage -= X`. תיקון חלקי אפשרי (נגזר מ"תיקון שיוריד את עלות התיקון ל־1000 או פחות"). ⚠️ יחס 1:1 בין תשלום להפחתת נזק — הנחת עבודה חזקה; לאימות DOSBox (כולל האם השחקן בוחר סכום או מתקן הכול).
5. **רציף סגור**: ב־20% מכניסות השחקן לרציף התיקונים — הרציף סגור עד סוף היום; למחרת פתוח תמיד. ⚠️ מקור: `התפלגות סיכויים.txt` בלבד (לא בפיענוח); צילומי המסך מאשרים שקיים מסך "רציף סגור". הנחת עבודה: ההגרלה מתבצעת בכניסה הראשונה ביום, והתוצאה קבועה לאותו יום.
6. **הפלגה בספינה פגועה** (`0 < damage ≤ 1000`): מותרת, אך חושפת לאירוע "החמרת נזק" בהפלגה (ראו `sailing-engine.md` §7) ומקטינה סיכויי בריחה מפיראטים.
7. **נזק ויזואלי**: מצב הספינה (תקינה/פגועה) משתקף במסך ההפלגה (אפיון המסכים) — תצוגה בלבד, ללא השפעה לוגית נוספת.
8. מנגנון הנזק הכללי (damaged) — הנוסחה המשותפת לשרטון/סערה/נסיעה פגועה — מוגדר ב־`sailing-engine.md` §7 כדי לרכז את נוסחאות ההפלגה; מערכת זו מחזיקה את המצב (`damage`) בלבד.

## 4. Formulas

```text
capacity: int = 100   # גדל: expand (+50/+100), פירטים (+50)
damage:   int = 0     # ש"ח; מצטבר

repair(x): require damage > 0 AND dock_open AND 1 ≤ x ≤ min(cash, damage)
           cash -= x; damage -= x          # ⚠️ יחס 1:1 — לאימות

can_sail: damage ≤ 1000
dock_open(day): rand(5) > 0                # 80% פתוח; מוגרל פעם ביום ⚠️
```

## 5. Edge Cases

- `damage > 1000` ואין די מזומן+בנק לתקן עד ≤1000 ⇒ אין דרך להמשיך ⇒ סיום משחק (ראו `scoring-endgame.md`).
- רציף סגור ביום 7 עם נזק >1,000: השחקן יכול רק לנוח ⇒ המשחק מסתיים כרגיל בסוף יום 7.
- תיקון בדיוק עד 1,000 (ולא מתחת) מספיק כדי להפליג.
- נזק חדש באמצע יום אחרי שכבר תוקן — האפשרות "לתקן" חוזרת לתפריט; הגרלת הרציף לא חוזרת (כבר נקבעה להיום) ⚠️.
- אין תקרת נזק — הנזק יכול לעלות על שווי כל הרכוש.

## 6. Dependencies

- `time-calendar.md` — חסימת הפלגה; הגרלת רציף יומית.
- `trading.md` / `banking.md` — תשלום תיקונים במזומן.
- `morning-events.md` — סירת דיג מוסיפה נזק; expand מגדיל קיבולת.
- `sailing-engine.md` — כל נוסחאות הנזק בהפלגה; מצב עומס מול קיבולת.
- `pirates.md` — נזק מקרב; +50 קיבולת בלכידה; נזק מקטין בריחה.
