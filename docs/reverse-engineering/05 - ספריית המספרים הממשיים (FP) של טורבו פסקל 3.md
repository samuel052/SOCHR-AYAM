# פרק 5 — ספריית המספרים הממשיים (FP) של טורבו פסקל 3

> פרק תשתית. טורבו פסקל 3 אינו משתמש במעבד מתמטי (8087); כל חישובי המספרים הממשיים (`Real`)
> נעשים בתוכנה דרך אוסף שגרות RTL. פענוח השגרות האלה חיוני: הן מופיעות בכל חישוב לא-שלם
> במשחק (כמויות, חלקים, נזקים, השוואות), ובלעדיהן אי אפשר לפענח את נוסחאות ההפלגה והקרב.

---

## 1. פורמט ה-`Real` של TP3
מספר ממשי = **6 בתים** (48 ביט). במהלך חישוב הוא מועבר על **מחסנית המעבד** כ-3 מילים.

מבנה הבתים (בזיכרון): `[exp] [m0] [m1] [m2] [m3] [m4]`
- **`exp`** (בית 0): מעריך מוטה. אם `exp == 0` → הערך הוא **0**.
- **סימן**: הביט העליון (bit 7) של הבית האחרון (`m4`).
- **מנטיסה**: 39 ביט (m0..m4, ללא ביט הסימן), עם ביט מוביל **1** מובלע.
- **ערך** = `(-1)^sign × (1 + mantissa/2³⁹) × 2^(exp − 129)`.

מפענח (מומש ונבדק):
```python
def tpreal(b6):
    if b6[0]==0: return 0.0
    sign=-1 if (b6[5]&0x80) else 1
    mant=b6[1]|(b6[2]<<8)|(b6[3]<<16)|(b6[4]<<24)|((b6[5]&0x7f)<<32)
    return sign*(1.0+mant/2.0**39)*2.0**(b6[0]-129)
```
דוגמאות שאומתו מהקוד: `80 00 00 00 00 40` = **0.75** · `90 00 00 00 C8 2F` = **45000.0**.

## 2. טבלת שגרות ה-FP (כתובות זיכרון)
כל השגרות פועלות על מחסנית ה-FP (אופרנדים נדחפים, תוצאה נדחפת חזרה).

| כתובת | שם | פעולה |
|---|---|---|
| `0x1973` | **FLoad** | דוחף `Real` ממשתנה בזיכרון (מצביע `es:di`) למחסנית |
| `0x1982` | **FLoadConst** | דוחף `Real` **קבוע** מ-6 הבתים שמיד אחרי הקריאה בקוד, ומדלג עליהם |
| `0x1993` | **FStore** | שומר `Real` מהמחסנית למשתנה בזיכרון |
| `0x19A6` | **FAdd** | חיבור |
| `0x19C1` | **FSub** | חיסור |
| `0x19D0` | **FMul** | כפל |
| `0x19DF` | **FDiv** | חילוק (בדיקת חלוקה באפס → שגיאת ריצה 2) |
| `0x19F7` | **FNeg** | שלילה (היפוך ביט הסימן) |
| `0x1A06` | **FAbs** | ערך מוחלט (איפוס ביט הסימן) |
| `0x1A0E` | **F=** | האם שווה → מחזיר בוליאני ב-AX |
| `0x1A28` | **F≠** | שונה |
| `0x1A42` | **F≥** | גדול-שווה |
| `0x1A5C` | **F≤** | קטן-שווה |
| `0x1A76` | **F>** | גדול-מ |
| `0x1A90` | **F<** | קטן-מ |
| `0x1B2F`, `0x1B38` | **Float** | המרת מספר שלם (int16) ל-`Real` |
| `0x1AFA` | **Trunc** | המרת `Real` ל-int16 (קיטום כלפי אפס) |
| `0x1AF6` | **Round** | המרת `Real` ל-int16 (עיגול) |
| `0x1AD4` | **RandomReal** | מספר ממשי אקראי ב-[0,1) (קורא ל-LCG `0x10E6`, פרק 2) |

> זיהוי בקוד: רצף טיפוסי הוא `…Float(int)… FLoadConst… FMul/FAdd… Trunc` — כלומר "המר לשלם
> אחרי חישוב ממשי". קבועי `Real` מוטבעים כ-6 בתים מיד אחרי `call 0x1982`.

## 3. סגירת פריטים פתוחים (בעזרת ספריית ה-FP)

### 3.1 כמות הטון באירוע מכירת-הסוחר (פרק 4 §2.2) ✅
`[0x2B9]` הוא המזומן. הקוד בונה תחילה:

```text
B = 0.25×cash + Random(Trunc(0.75×cash)+1)
```

ואז מחשב לפי מחיר המרכז של הסחורה:

```text
tons = 5×Trunc((B/centerPrice)/5 + 1)
```

הכמות היא כפולה של 5 ונגזרת מן המזומן וממחיר המרכז, לא ממחיר ההצעה. אם
`offerPrice×tons > cash` או שאין מזומן חיובי, האירוע אינו ישים וכל הבורר מופעל מחדש.

### 3.2 שערי השחקן העשיר (פרק 3 §2.2) ✅
לאחר שמועמד עבר את מניעת החזרה קיימים **שני שערים** (זיכרון `0x6748` ו־`0x677B`):
```
אם cash > 20000 וגם Random(6)==1 → R := 15
אם cash > 45000 וגם Random(6)==1 → R := 15
```

שתי קריאות `Random(6)` נצרכות תמיד, גם כשהמזומן אינו עובר את הסף, בגלל הערכת Boolean
לא־מקוצרת. `R=15` הוא אירוע הרחבת ספינה — לא "אין אירוע" ולא ביטול זעזוע. הכפייה
מתרחשת אחרי מניעת החזרה ולכן יכולה לעקוף אותה.
