# פרק 3 — אירועי תחילת יום (מזג אוויר + בורר האירוע)

> **עדכון אימות סופי:** המפרט המחייב והמלא הוא
> [10 - מפרט מנוע מאומת סופית.md](10%20-%20מפרט%20מנוע%20מאומת%20סופית.md).

> פרק זה מפענח את רצף תחילת היום **מהקוד**, ומאומת מול צילומי המסך (ראו `00 - מפת דרכים`).
> כל יום (מהשני) כולל שני שלבים נפרדים: (א) **קביעת מזג אוויר**; (ב) **הגרלת אירוע יומי**.
> כל 30 ערכי ההגרלה ממופים לאירוע — **אין מצב "אין אירוע"**. המיפוי כאן הוא 1:1 מול 7 סוגי
> האירוע שנראים במשחק.
>
> כל הסעיפים בפרק אומתו בקוד ובאודיט הבינארי הסופי.
>
> מוסכמת הסתברות: שברים כמו `1/6` הם קיצור קריא לתנאי על `Random(6)`. ההסתברות הביטית
> המדויקת כוללת את הטיית ה־modulo הזעירה של TP3 כאשר `n` אינו מחלק את 32768 (פרק 2).

המשתנים המרכזיים שזוהו בקוד:
| כתובת | תוכן |
|---|---|
| `[0x2AF]` | היום הנוכחי (1–7) |
| `[0x2C9]` | מספר האירוע התקף של אתמול (מניעת חזרת אותו זוג) |
| `[0x2D4]/[0x2D6]/[0x2D8]` | מחירי מרכז: נחושת/זיתים/חיטה (פרק 2) |
| `[0x2F8]/[0x2FA]/[0x2FC]` | **מערך המטען** (נחושת/זיתים/חיטה בטון) = `[0x2F6+c×2]`; זוהה דרך שגרת הגניבה והפאנל |
| `[0x2B3]` | **נזק הספינה** (מצטבר, בשקלים) — נוסף בהתנגשות+נזקי-הפלגה, מתוקן ב"תיקון" (18 שימושים) |
| `[0x2B9]` | **מזומן** (כספומזומן) — ה-FP המרכזי, 76 שימושים; מוצג בפאנל; נבדק בשער "עשיר" (>45000) |
| `[0x2BF]` | **יתרת בנק** — 21 שימושים; נגרעת באירוע הרחבת-ספינה ובפעולת הבנק ("מחשבונך בבנק") |

## 1. קביעת מזג האוויר ✅ (שגרה `0x60F4`, מוצגת ע"י `0x4956`)
לפני האירוע, נקבע מזג האוויר ליום:
```asm
mov ax, 8 ; call 0x10DA      ; Random(8) → 0..7
cmp ax, 3                    ; תנאי1 = Random(8) < 3   (סיכוי 3/8)
mov ax, [0x2AF] ; cmp ax, 1  ; תנאי2 = (היום ≠ 1)
and ...                      ; מזג רע ⇔ תנאי1 וגם תנאי2
  → אם רע:  mov ax,3; call Random; add 1   ; נמל סוער = Random(3)+1 (תורכיה/ישראל/מצרים)
  → אם טוב: אין סערה (רגוע בכל הנמלים)
```
**מסקנה:**
- **יום 1: תמיד רגוע.**
- **ימים 2–7: בהסתברות 3/8 = 37.5% מזג אוויר רע** → **סערה בנמל אחד אקראי** (`Random(3)+1`).
  אחרת (62.5%) — רגוע בכל הנמלים.
- מזג האוויר מוצג במסך (`goodwthr.scr` / `badwthr.scr`, שגרת `0x4956`), והנמל הסוער משפיע על
  סיכוני ההפלגה לאותו נמל (ראו פרק 6).

## 2. שער היום והגרלת האירוע ✅
```asm
; ברצף תחילת היום (0xB63F):
mov ax,[0x2AF] ; cmp ax,1 ; jg → call 0x6166   ; אירוע רק אם היום > 1
; בורר האירוע (0x64AE):
mov ax,30 ; call 0x10DA ; add ax,1              ; R = Random(30)+1  ∈ [1,30]
mov [bp-6], ax
```
**`R = Random(30)+1`** הוא הערך היחיד שקובע את אירוע היום (טבלה §3).

### 2.1 תנאי ביטול א' — מניעת חזרה (הגרלה מחדש) ✅
`[0x2C9]` שומר את מספר האירוע התקף של אתמול. הבורר בודק אם R שייך לאותו זוג מבין
`1–2, 3–4, ... 29–30`; אם כן — קופץ אחורה ל-`0x64B9` ומ**גריל מחדש**. משפחות רחבות
מחולקות לזוגות: לדוגמה 13–14 אינו מונע 15–16 ביום הבא.

### 2.2 שערי "שחקן עשיר" ✅
לאחר מועמד תקף נצרכות תמיד שתי הגרלות, לפי הסדר:
```
אם [0x2B9] > 20000.0 וגם Random(6)==1 → R := 15
אם [0x2B9] > 45000.0 וגם Random(6)==1 → R := 15
```
הערך 15 נופל בתחום 13–18, ולכן התוצאה היא **כפיית אירוע "הרחבת ספינה"**. זהו מנגנון ניקוז-כסף
לשחקן עשיר — לא ביטול ל"כלום". (השוואת `F>` עם 45000.0; ראו פרק 5.)

## 3. טבלת האירועים (מיפוי 1:1 מאומת — קוד + מסך)
| R | אירוע | הסת' גולמית | גבול `cmp` |
|---|---|---|---|
| 1–12 | זעזוע מחיר (6 וריאנטים, §4) | 40% | עד 11/12@`0x6996` |
| 13–18 | הרחבת ספינה (§5) | 20% | 13/18@`0x69FB` |
| 19–20 | נטישת צוות (§6) | 6.7% | 19/20@`0x6F6B` |
| 21–22 | **גניבה** (§7) | 6.7% | 21/22@`0x719D` |
| 23–26 | סוחר קונה ממני (§8, פרק 4) | 13.3% | 23/26@`0x72B8` |
| 27–28 | סוחר מוכר לי (§8, פרק 4) | 6.7% | 27/28@`0x7920` |

ההסתברויות מושפעות מ-§2.1 (re-roll מעלה מעט את חלקו של הזעזוע) ומ-§2.2 (הסטה להרחבה לעשיר).

## 4. זעזוע מחיר (R 1–12) ✅
שינוי חד במחיר **סחורה אחת בנמל אחד** (נמל = `Random(3)+1`), נכתב למשבצת המחיר דרך `0x6172`.
מוצג: "מחיר ה<סחורה> ב<נמל> קפץ/ירד ל-N שקלים!!".

| R | סחורה/כיוון | מחיר חדש | טווח |
|---|---|---|---|
| 1–2 | נחושת ↑ | 3000+1100+Random(5)×100 | 4100–4500 |
| 3–4 | זיתים ↑ | 500+200+Random(4)×50 | 700–850 |
| 5–6 | חיטה ↑ | 50+20+Random(5)×5 | 70–90 |
| 7–8 | נחושת ↓ | 3000−1100−Random(5)×100 | 1500–1900 |
| 9–10 | זיתים ↓ | 500−150−Random(3)×50 | 250–350 |
| 11–12 | חיטה ↓ | 50−15−Random(3)×5 | 25–35 |
(אומת מול מסך: "מחיר החיטה במצרים ירד ל-25" — בטווח.)

## 5. הרחבת ספינה (R 13–18) ✅
- **תוספת קיבולת** = `(Random(2)+1)×50` → 50 טון (50%) או 100 טון (50%).
- **עלות נקובה** = `(2×טון + Random(טון))×10` ש"ח:
  50 טון → 1000–1490 ש"ח · 100 טון → 2000–2990 ש"ח.
- מסך: "אתה יכול להגדיל את גודל ספינתך ב-N טון תמורת M שקל. (כ/ל)".
> **פירוק תשלום מאומת בקוד:** מזומן בלבד אם הוא גדול מן המחיר; אחרת בנק בלבד אם הוא גדול
> מן המחיר; אחרת מזומן+בנק אם סכומם גדול מן המחיר; אחרת הסחורה בעלת שווי־המרכז הגבוה ביותר.
> אם שווייה מכסה את המחיר נגבים `Round(מחיר/מרכז)` טון. אחרת נגבה כל המלאי והיתרה נלקחת
> ממקור יחיד: מזומן אם `מזומן>בנק` או `מזומן>=שווי המטען`, ואחרת בנק. אין השלמה מן המקור
> השני, ולכן באגי שוויון, עיגול וקיטום עשויים לתת את ההרחבה גם בתשלום חסר.

## 6. נטישת צוות (R 19–20) ✅ (מטפל `0x6F6B`–`0x719D`)
מסך: "הצוות נוטש את הספינה. אתה יכול: 1. לקחת צוות חדש · 2. לנסות לפתות אותם להישאר".

**תנאי יום נוסף (חריג):** האירוע פעיל **רק בימים 2–5**. הקוד בודק `cmp [0x2AF],6; jl` — אם
**היום ≥ 6**, האירוע מדולג: מציב `result=0` (`0x7193`) וקופץ ל-`0x64B2` → **הגרלה מחדש** של אירוע אחר.

**זרימת המטפל:**
1. טוען מסך הצוות (`[0xAE8]`) ומציג פאנל מלאי: מטען `[0x2F8]/[0x2FA]/[0x2FC]` + מזומן `[0x2B9]`.
2. תפריט שתי אפשרויות (שגרת תפריט `0x4D51`, ax=2), הבחירה ב-`[bp-0x18]`:
    - **אפשרות 1 — "לקחת צוות חדש":** מתקדם מיד **מונה היום** (`[0x2AF] += 1`, קוד `0x717D`)
      וחוזרים לתפריט בלי אתחול בוקר חדש; במנוחה הבאה מתקדם היום פעם נוספת.
   - **אפשרות 2 — "לנסות לפתות אותם להישאר":** דיאלוג אינטראקטיבי (`0x579A` → `0x58E9`) — **פוענח
     במלואו**. השחקן מציע **מזומן + סחורה**, והצוות מתרצה אם ההצעה עולה על דרישה פנימית
     אקראית הנגזרת מהרכוש:

     1. **הרכוש הכולל** = מזומן + שווי המטען (שגרה `0x4648`, זיכרון `0x4648`):
        `שווי מטען = Σ_c( cargo[c] × center_price[c] )` (מחירי המרכז 3000/500/50), ו-
        `רכוש = שווי מטען + מזומן [0x2B9]`.
     2. **דרישת הצוות** (זיכרון `0x5C30`–`0x5C3F`):
        > **דרישה = רכוש ÷ ( Random(6) + 4 )**
        כלומר חלוקה במספר אקראי בין 4 ל-9 → **הצוות דורש בין 1/9 (~11%) ל-1/4 (25%) מהרכוש**,
        מוגרל מחדש בכל פעם.
     3. השחקן מזין כמה **מזומן** וכמה **טון מכל סחורה** להציע (קלט `0x4F59`, מאומת שלא יעלה על
        המצוי). **שווי ההצעה** = `מזומן מוצע + Σ_c( טון מוצע[c] × center_price[c] )`.
     4. **ההכרעה** (זיכרון `0x5C50`, השוואת `F>`):
        - אם **שווי ההצעה > הדרישה** → "הצוות קיבל את הצעתך": הצוות **נשאר**, והמזומן+הסחורה
          שהוצעו **מנוכים** מהשחקן.
        - אחרת → "הצוות סרב להצעה": הצוות **עוזב** (צוות חדש + אובדן זמן).

> **הערה:** הבדיקה מבוססת על **מזומן** `[0x2B9]` ומטען — **לא** על יתרת הבנק `[0x2BF]`.
> (בדיקת בנק קיימת ב**אירוע ההרחבה**, §5.) הסף הוא **אחוז אקראי מהרכוש** (1/4–1/9), בדיוק
> כפי שהתואר — וכעת מאומת בקוד עם הנוסחה המלאה.

## 7. גניבה (R 21–22) ✅
מסך: "גנבים פרצו לספינתך באמצע הלילה. הם גנבו K טון <סחורה>". המטפל קורא לשגרת הגניבה
**`0x5CC9`**, שפוענחה במלואה:
1. מנסה תחילה גניבת מזומן: `10×Trunc(מזומן/(40+Random(40)))`.
2. רק אם התוצאה אפס, בוחרת את הסחורה הראשונה שיש ממנה יותר משני טון.
3. כמות נגנבת = `Trunc( cargo[c] × (20 + Random(21)) / 100 )` → **20%–40% מהמטען** של אותה סחורה
   (מינימום 1 טון).
4. אם גם אין מטען ישים, האירוע נפסל והבורר מתחיל מחדש.

> כך זוהה ש-`[0x2F6]` הוא **מערך המטען** (הכמויות במחסן). הגניבה תמיד פוגעת בסחורה אחת בלבד.

## 8. הצעות הסוחר (R 23–28) — פירוט בפרק 4
- **R 23–26: סוחר קונה ממני** ("סוחר זקוק בדחיפות"). מחיר לטון לפי סחורה:
  נחושת `שוק+Random(30)×50−600` · זיתים `שוק+Random(70)×10−300` · חיטה `שוק+Random(14)×5−40`.
- **R 27–28: סוחר מוכר לי**. התקציב הוא `0.25×מזומן+Random(Trunc(0.75×מזומן)+1)`;
  הכמות היא הכפולה הבאה של 5 לפי מחיר המרכז. הצעה שאינה ניתנת לתשלום נפסלת ונגרלת מחדש.

## 9. נזק / התנגשות ספינה (R 29–30) ✅
מסך: "ספינת דייג התנגשה בך ונגרם לספינתך נזק בשווי N". המטפל (זיכרון `0x7C16`–`0x7CC0`) פוענח:
```asm
call 0x4648            ; שווי המטען = Σ cargo[c]×center[c]
FLoad [0x2B9] ; FAdd   ; רכוש = שווי מטען + מזומן
mov ax,80 ; Random ; add 150 ; Float   ; מחלק אקראי = Random(80)+150 = 150..229
FDiv ; Trunc           ; Trunc( רכוש / (Random(80)+150) )
pop cx ; imul cx       ; ×10
mov [bp-0x16], ax      ; = שווי הנזק
אם [bp-0x16] > 0:  [0x2B3] := [0x2B3] + [bp-0x16]    ; הוספת הנזק לצובר
```

> **נוסחת הנזק:** `10×Trunc((מזומן+שווי-מטען)/(Random(80)+150))`. הערך נצבר
> ב־`[0x2B3]` ומתוקן במספנה; תוצאת אפס פוסלת את האירוע ומפעילה מחדש את הבורר כולו.

## 10. סיכום הפרק
**אומת ✅:**
- **מזג אוויר** (§1): יום 1 רגוע; ימים 2–7 — 3/8 לסערה בנמל `Random(3)+1`.
- **הגרלה:** `R = Random(30)+1`; **כל 30 → אירוע**.
- **תנאי ביטול:** re-roll לפי 15 זוגות המספרים; לאחר מועמד תקף שערים ב־20,000 וב־45,000
  כופים הרחבה בתוצאת `Random(6)==1`.
- **מיפוי 1:1 מאומת** (§3): זעזוע 1–12, הרחבה 13–18, צוות 19–20, **גניבה 21–22**, סוחר-קונה
  23–26, סוחר-מוכר 27–28, **נזק/התנגשות 29–30**.
- נוסחאות מלאות: זעזוע (§4), הרחבה (§5), גניבה (§7), סוחר-קונה (§8).
- משתנים שזוהו: `[0x2F6]`=מטען, `[0x2B3]`=נזק, `[0x2AF]`=יום, `[0x2C9]`=אירוע אתמול.

**משתני הכסף — זוהו סופית (לא נדחה לפרק נפרד):** `[0x2B9]`=מזומן · `[0x2BF]`=בנק · `[0x2B3]`=נזק.
אירוע ההרחבה משתמש בפירוק מזומן/בנק/מטען שב§5; אירוע הצוות בודק מזומן+מטען בלבד.

**נטישת צוות — פוענח במלואו ✅** (§6): דרישה = רכוש ÷ (Random(6)+4) (1/4–1/9 מהרכוש);
הצעה = מזומן+סחורה; קיבול אם הצעה > דרישה.
**נזק/התנגשות — פוענח במלואו ✅** (§9): נזק = 10×Trunc((מזומן+שווי-מטען) / (Random(80)+150)).

**שגרת-עזר משותפת שזוהתה:** `0x4648` = **שווי המטען** (`Σ cargo[c]×center_price[c]`) — משמשת
את הפיתוי (§6) ואת ההתנגשות (§9). הניקוד הסופי אינו משתמש בשווי המטען אלא במזומן+בנק בלבד.

> **פרק 3 הושלם — כל פינה סגורה.** אין פריטי 🟡 פתוחים.
